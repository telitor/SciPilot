## 2. 交付目录说明

### Python demo

- `xfyun_knowledge_base/client.py`：鉴权、上传、状态轮询、问答、知识库管理和文件删除。
- `batch_upload.py`：论文预检、SHA-256 去重、批量上传、断点续传、失败清理和向量化等待。

官方 demo 自带的 Python `背影.txt` 和 Java `test.txt` 已删除，交付包中不再包含会被误上传的测试文档；旧版 WebSocket、硬编码凭据和陈旧编译产物也已移除。

## 3. 凭据配置规范

后端运行环境必须设置：

```text
XFYUN_KB_APP_ID=<讯飞控制台 AppID>
XFYUN_KB_API_SECRET=<控制台重新生成的 APISecret>
XFYUN_KB_REPO_ID=193588d54888467f8d18001408bc22aa
XFYUN_KB_PAPER_DIR=<论文目录绝对路径>
XFYUN_KB_BASE_URL=https://chatdoc.xfyun.cn
```

规范：

- 截图中出现过的 APISecret 视为已暴露，生产前必须在控制台轮换。
- `.env` 和 `.xfyun-upload-state.json` 已被 Git 忽略，不得提交或放入公开交付包。
- 通过公司 Secret Manager、部署平台或安全渠道向后端人员提供新 Secret。
- 凭据只能存在于后端；禁止写入前端、日志、数据库明文字段或接口响应。
- 部署主机启用 NTP，签名时间与讯飞服务器误差必须小于 5 分钟。

每次请求使用下列鉴权头：

```text
appId: 应用 ID
timeStamp: 当前 Unix 秒级时间戳
signature: Base64(HMAC-SHA1(MD5(appId + timeStamp), APISecret))
```

删除完成后，失败文件的本地断点记录会同步移除，可重新上传。

### 4.2 本地预检

```powershell
python .\batch_upload.py
```

预期结果为：100 个可用 PDF、5 个哈希重复副本、95 个候选、0 个超限文件。默认不产生任何远程写入。

### 4.3 小批验证

```powershell
python .\batch_upload.py --execute --limit 3
```

必须同时满足以下条件才能继续全量构建：

1. 3 篇上传响应 `code=0`，且均获得 `fileId`、`sid`。
2. 3 篇最终状态全部为 `vectored`，不得存在 `failed`。
3. 使用现有 `repoId` 问答能收到 `status=2` 结束帧。
4. 至少一次返回 `status=99` 文档引用帧，且引用论文正确。

若文件状态为 `failed`，立即停止，不要全量上传：记录 `fileId/sid`，清理失败资源后重试。普通可复制文字 PDF 优先尝试 `--parse-type TEXT`，扫描版 PDF 使用 `--parse-type OCR`；仍失败则携带 `sid` 向讯飞提交工单。

### 4.4 全量构建

小批验证全部通过后执行：

```powershell
python .\batch_upload.py --execute
```

脚本行为：

- 上传时直接传 `repoIds=[193588d54888467f8d18001408bc22aa]`，无需再次调用知识库添加文件。
- 默认 `parseType=AUTO`、`needSummary=false`。
- 每篇上传成功后立即把 `fileId/sid/SHA-256` 写入 `.xfyun-upload-state.json`。
- 中断后重复执行同一命令，已成功文件自动跳过。
- 文件逐篇等待 `vectored`；单篇失败会记录并继续处理其他文件，不会让整个批次丢失断点。

只查询已上传文件状态、不上传新文件：

```powershell
python .\batch_upload.py --status-only
```

## 5. 后端业务调用流程

```text
上传文档
  → 保存 fileId 和 sid
  → 轮询 /openapi/v1/file/status
  → vectored 后允许问答
  → POST /openapi/v2/chat
  → 将回答帧和引用帧分别转发给前端
```

文件状态通常依次为：

```text
uploaded → texted/ocring → spliting → splited → vectoring → vectored
                                                        └→ failed
```

问答采用 HTTP SSE：

- `status=0`：首帧。
- `status=1`：中间回答帧。
- `status=2`：回答结束帧。
- `status=99`：文档引用帧，单独保存，不要拼入回答正文。
- `repoIds` 和 `fileIds` 必须且只能传一个；本项目正式问答统一使用现有 `repoIds`。

Python 最小调用：

```python
import os

from xfyun_knowledge_base import XfyunKnowledgeBaseClient

client = XfyunKnowledgeBaseClient.from_env()  # 应在服务生命周期内复用
repo_id = os.environ["XFYUN_KB_REPO_ID"]

request = client.build_chat_request(
    [{"role": "user", "content": "论文中如何定义和度量软件质量？"}],
    repo_ids=[repo_id],
)

for frame in client.iter_chat(request):
    if frame.get("status") == 99:
        save_references(frame)
    else:
        push_answer(frame.get("content") or "")
```

Java 中通过依赖注入复用一个 `XfyunKnowledgeBaseClient`/`OkHttpClient` 实例，不要每个请求重新创建连接池。

## 6. 已封装接口

| 业务 | API | Python | Java |
| --- | --- | --- | --- |
| 本地文件上传 | `/openapi/v1/file/upload` | `upload_file` | `uploadFile` |
| URL 文件上传 | `/openapi/v1/file/upload` | `upload_url` | `uploadUrl` |
| 文件状态查询 | `/openapi/v1/file/status` | `file_status` | `fileStatus` |
| 删除文件及向量 | `/openapi/v1/file/del` | `delete_files` | `deleteFiles` |
| 等待可问答 | 轮询状态接口 | `wait_until_vectored` | `waitUntilVectored` |
| 文档/知识库问答 | `/openapi/v2/chat` | `iter_chat` / `chat` | `chat` |
| 创建知识库 | `/openapi/v1/repo/create` | `create_repository` | `createRepository` |
| 知识库添加文件 | `/openapi/v1/repo/file/add` | `add_repository_files` | `addRepositoryFiles` |
| 知识库移除文件 | `/openapi/v1/repo/file/remove` | `remove_repository_files` | `removeRepositoryFiles` |
| 删除知识库 | `/openapi/v1/repo/del` | `delete_repository` | `deleteRepository` |
| 删除库及文件 | `/openapi/v1/repo/del-with-files` | `delete_repository(delete_files=True)` | `deleteRepository(..., true)` |

`del-with-files` 会删除知识库包含的文件和向量数据，业务接口不得直接暴露该能力；必须进行管理员鉴权、二次确认和操作审计。

## 7. 上传与维护规范

- 支持 `txt/md/doc/docx/pdf/xls/xlsx/csv/jpg/jpeg/png/bmp/ppt/pptx`。
- 单文件不超过 20MB、文本不超过 100 万字符。
- 以 SHA-256 作为去重依据；文件名相同但哈希不同的文件需人工确认版本。
- 论文文件名保留“序号_年份_期刊_标题”结构，禁止覆盖原始论文。
- 写操作不做无条件自动重试；网络中断后先查询断点状态，防止重复上传。
- 日志记录内部任务 ID、`fileId`、`sid`、HTTP 状态、业务 `code` 和耗时，不记录 APISecret 或论文全文。
- 状态查询可对 `429/5xx` 做指数退避；建议轮询间隔不少于 5 秒。
- 所有删除操作必须记录操作者、目标 ID、时间和结果。

常见鉴权错误：

- `401`：检查鉴权头、签名算法和 APISecret。
- `403`：检查服务器时间，通常为时间戳偏差过大。
- `405`：检查 AppID 是否已开通知识库 API 权限。

## 8. 构建完成验收标准

- 95 篇唯一论文全部存在于知识库，状态均为 `vectored`。
- 5 个重复副本未上传，失败文件数为 0。
- 上传清单中的本地路径、SHA-256、`fileId` 和 `sid` 可追溯。
- 至少抽查 10 个跨年份、跨期刊问题，回答能返回正确论文引用。
- 后端 SSE 能正确区分正文、思考内容和 `status=99` 引用。
- 前端无法获取 AppID/APISecret，日志与 Git 中无凭据。
- 讯飞控制台中的文件数量、脚本清单和知识库文件列表一致。
